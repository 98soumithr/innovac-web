# Innovac Ceramic — Build Plan for Claude Code

## 0. Why this setup works well with Claude Code
- **A small CLAUDE.md with the detail in `docs/`.** Claude Code loads CLAUDE.md every session, so it stays
  short. It reads the docs when a phase needs them.
- **Content is separate from templates.** Products, families and industries are markdown files that are
  checked against a schema. Claude writes a template once. After that, adding a page means adding a
  content file, not writing more code.
- **Colours live in one place.** They are defined once in `@theme`. A lint script blocks raw hex values
  in components, so the look can't drift.
- **Guard scripts catch mistakes.** `lint-copy` blocks forming-process words, `lint-tokens` blocks raw
  hex, and `todo` lists every missing fact. Claude runs them itself.
- **Claude checks its own screenshots.** `npm run shots` takes screenshots of every page at 390px and
  1440px. Claude compares them with the reference mockup and fixes the differences.
- **One phase per session.** Run `/clear` between phases. Every phase ends with a passing build and a
  commit, so a bad session can be rolled back.

## 2. Before you start (you, not Claude Code)
1. Create an empty GitHub repo `innovac-web`. Unzip this kit into it and commit it as "docs: build kit".
2. Create a free **Web3Forms** access key for the sales inbox (needed in Phase 6). Hosting is GitHub
   Pages on the public repo, so no hosting account is needed.
3. Collect the facts in `docs/content-checklist.md`. The build can start without them, since they show up
   as `[[TODO]]`s, but the site can't **launch** without them.
4. Book the photographer (design-system §6). This is the longest lead-time item.
5. Make sure you have the GoDaddy login for `innovacceramic.com` (the registrar). The Hostinger login is
   lost, so at launch the nameservers move back to GoDaddy (Phase 9).

## 3. Phases and prompts
Start Claude Code in the repo. Use **Plan mode** (Shift+Tab) for Phase 1, and approve the plan before it
writes code. Run `/clear` between phases. Paste each prompt as written.

### Phase 1 — Scaffold, tokens, fonts, guard scripts
> Read CLAUDE.md, docs/design-system.md and docs/build-plan.md §1. Scaffold the Astro project exactly to the
> folder structure in build-plan §1: TypeScript strict, Tailwind v4 via @tailwindcss/vite, static output,
> `base` from `BASE_PATH`, sitemap, and `trailingSlash: 'always'`, plus the GitHub Pages deploy workflow. Put every colour token, the type scale, spacing and
> radius from design-system §1–3 into `@theme` in src/styles/global.css. Self-host the fonts with
> Fontsource and preload the two critical files. Write scripts/lint-copy.mjs, lint-tokens.mjs, todo.mjs and
> shots.mjs, and wire up the npm scripts from CLAUDE.md. Create src/data/site.ts with every field from
> site-plan §6 set to null, except the brand name. Add the redirects from site-plan §5. Finish with
> `npm run build && npm run check` passing, then commit "phase 1: scaffold".

### Phase 2 — Components and styleguide
> Build every component in design-system §5 in src/components, using token classes only. Create
> /styleguide/ (noindex) that renders each component in all its variants and states, on both carbon and
> paper. Build BaseLayout with the header, footer and MobileActionBar (the mobile menu is the only JS). Run
> `npm run shots` and compare /styleguide/ with docs/reference/homepage-mockup.html at 1440 and 390:
> match the type sizes, spacing, borders and colours. Fix the differences. Build, check, then commit
> "phase 2: components".

### Phase 3 — Homepage
> Build / exactly to site-plan §3 Home and the reference mockup (the "How we work" section is removed and
> must not be added back). Use PhotoFrame placeholders for photos and site.ts for every figure. Run shots at
> 390, 768, 1280 and 1440. Compare side by side with the mockup and list the remaining differences, then fix
> them. Check that Lighthouse mobile scores ≥ 95 on /. Commit "phase 3: home".

### Phase 4 — Content model, product and family pages
> Implement src/content.config.ts from site-plan §6 and the build validation in src/lib/validate.ts.
> Build products/[slug].astro, which renders the family and product templates per site-plan §3. Write the 3
> family files and 10 product files. Write original, professional copy in the voice of design-system §8.
> Use `[[TODO: …]]` for every fact you don't have (sizes, specs, grades, materials). Never mention the
> forming process. Filter candles go in hot-gas-filtration. Write 4–6 FAQs per product aimed at the keywords
> in site-plan §4.2. Build, check, shots, then commit "phase 4: products".

### Phase 5 — Remaining pages
> Build /products/, /custom-ceramic-fibre-shapes/, /plant-and-quality/, /industries/ and its 5 industry
> pages, /about/, /downloads/, /contact/, /privacy/ (DPDP Act 2023, covering data collected by the RFQ form and
> 180-day file retention), /thank-you/ and 404, all per site-plan §3. Build, check, shots, then commit
> "phase 5: pages".

### Phase 6 — Request a quote (form and Web3Forms)
> Build RfqForm and /request-a-quote/ per site-plan §3, "Request a quote". The form posts with `fetch` to
> Web3Forms (`https://api.web3forms.com/submit`) using `PUBLIC_WEB3FORMS_KEY`, with the Web3Forms honeypot,
> a reference number (`INV-YYMMDD-XXXX`) generated in the browser and included in the subject, and the page
> the buyer came from. Add `?product=` pre-fill, inline accessible errors, keep typed data on failure, a
> WhatsApp fallback, and a redirect to /thank-you/?ref=. Drawing uploads: Web3Forms attachments need a paid
> plan, so decide with the owner between (a) paid attachments or (b) no upload field and "send the drawing
> on WhatsApp or by email" copy. Add Playwright tests for validation and for a mocked successful submit.
> Commit "phase 6: rfq".

### Phase 7 — SEO layer
> Implement Seo.astro and src/lib/seo.ts per site-plan §4.3–4.4: titles, descriptions, canonical, OG and
> Twitter tags, build-time OG images per page, and JSON-LD for Organization, LocalBusiness, Product and
> BreadcrumbList. Configure sitemap exclusions and robots.txt. Add Cloudflare Web Analytics and the events from §4.6. Verify
> every page has exactly one H1, a unique title and a unique description, then write a report to
> docs/seo-audit.md. Commit "phase 7: seo".

### Phase 8 — Quality pass
> Run the full audit:
> - Lighthouse mobile on /, one family page, one product page, and /request-a-quote/ (target ≥ 95 in all
>   four categories).
> - axe on every route, with no serious or critical issues.
> - Keyboard-only walkthrough of the header, the mobile menu and the RFQ form.
> - Check the image weight budgets from design-system §6 and the JS budget from site-plan §4.5.
> - `npm run todo` for the outstanding list.
> Fix everything you can, list what needs input from Innovac, and commit "phase 8: qa".

### Phase 9 — Launch (with you)
1. Replace the `[[TODO]]`s using `docs/OUTSTANDING.md` and add the real photos. Re-run
   `npm run build && npm run check && npm run shots`.
2. Add `public/CNAME` containing `innovacceramic.com`, and remove `BASE_PATH` from the deploy workflow so
   the site builds at `/`. Push and check the Actions run is green.
3. In GoDaddy, **Change Nameservers** → "GoDaddy default", then in GoDaddy DNS add:
   - `A @` → 185.199.108.153, 185.199.109.153, 185.199.110.153, 185.199.111.153
   - `AAAA @` → 2606:50c0:8000::153, 2606:50c0:8001::153, 2606:50c0:8002::153, 2606:50c0:8003::153
   - `CNAME www` → `98soumithr.github.io`
   - **Keep email working:** `MX @` 5 `mx1.hostinger.com` and 10 `mx2.hostinger.com`, and
     `TXT @` `v=spf1 include:_spf.mail.hostinger.com ~all` (or the records of a new mail provider).
4. In the repo's Settings → Pages, set the custom domain to `innovacceramic.com` and tick
   **Enforce HTTPS** once the certificate is issued.
5. Test every old URL in site-plan §5 and confirm it lands on the right page. Send a real RFQ and check
   the email arrives.
6. Complete the Search Console, Bing, Google Business Profile and NAP checklist in site-plan §4.6.

## 4. Working tips for Claude Code
- If the look drifts, give it a screenshot of the mockup section and its own screenshot, and say
  "match this: list the differences first, then fix".
- Ask for **diffs, not rewrites**: "Change only X in Y.astro."
- Once the templates exist, use subagents to write several content files in parallel ("write the 5 industry
  files in parallel using the industries schema").
- Keep a `docs/decisions.md` log. After any design decision, ask Claude Code to add one line.
- Never paste secrets into chat. They live in `.env` locally and in GitHub Actions secrets or variables.
